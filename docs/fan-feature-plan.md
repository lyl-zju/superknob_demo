- 设备 token：已取得并存放在被 Git 忽略的 `include/secrets.h`。
- 实机握手成功：设备返回 `xiaomi.fan.p69 v1.0.5`。
- 只读属性验证成功：电源、模式、1–100 风速、左右摆风和水平摆角均返回 `code: 0`。
- MIoT 服务：风扇 `siid=2`。
- 风速：`piid=5`，范围 `1..100`。
- 左转：`aiid=4`；右转：`aiid=5`。动作本身不接受角度参数。
- 主页面中已有未启用的风扇入口、图标资源、页面枚举和函数声明，可沿现有架构扩展。

## 2. 目标交互

```text
主页面
└─ 风扇
   ├─ 开关
   │  └─ 轻触：在开/关之间切换，颜色和文字跟随设备状态
   ├─ 风速
   │  ├─ 旋钮：1–100 实时调节
   │  └─ 轻触：返回风扇菜单
   ├─ 左右转动
   │  ├─ 旋钮左转：按转动量累计发送左转动作
   │  ├─ 旋钮右转：按转动量累计发送右转动作
   │  └─ 轻触：返回风扇菜单
   └─ 返回
      └─ 轻触：返回主页面
```

触摸键不承担长按、双击或手势识别，避免改变现有硬件输入的不确定性。

## 3. 代码分层

### 3.1 私密配置层

- 保留 `include/secrets.example.h` 作为可提交模板。
- `include/secrets.h` 仅存本机 Wi-Fi、风扇 IP 和 token，并保持 Git 忽略。
- 增加编译期校验：token 必须是 32 个十六进制字符；占位符配置给出明确错误。
- 后续如更换路由器，只修改私密配置，不修改业务代码。

### 3.2 miIO 传输层

建议文件：

```text
src/miot/miio_transport.h
src/miot/miio_transport.cpp
```

职责：

- UDP 54321 握手，获取设备 ID 与设备时间戳。
- 将 token 从十六进制转为 16 字节。
- 使用 MD5 派生 AES key 和 IV。
- AES-128-CBC 加密/解密与 PKCS#7 填充。
- 生成并校验 miIO 32 字节包头与摘要。
- 管理递增请求 ID、超时、有限重试和错误码。
- 不包含任何风扇属性编号或 LVGL 逻辑。

### 3.3 风扇设备层

建议文件：

```text
src/miot/xiaomi_fan_p69.h
src/miot/xiaomi_fan_p69.cpp
```

职责：

- `readState()`：读取电源、模式、风速、摆风状态。
- `setSpeed(1..100)`：写 `siid=2, piid=5`。
- `setPower(bool)`：写 `siid=2, piid=1`。
- `turnLeft()`：调用 `siid=2, aiid=4`。
- `turnRight()`：调用 `siid=2, aiid=5`。
- 将原始 MIoT 响应转换为稳定的项目级结果类型。
- 拒绝越界值，不让 UI 直接拼 JSON。

### 3.4 异步控制层

建议文件：

```text
src/fan_controller.h
src/fan_controller.cpp
```

职责：

- 使用独立 FreeRTOS 队列和网络任务，禁止在 LVGL 回调中阻塞等待 UDP。
- 风速采用“最新值覆盖”策略：界面立即变化，网络侧约每 `150–300 ms` 合并一次。
- 方向采用有界累计量：编码器变化累加，网络任务按固定节奏逐步消化。
- 限制队列长度和连续重试次数，断网时不无限堆积动作。
- 向 UI 返回连接中、成功、超时和配置错误状态。

### 3.5 UI 层

建议文件：

```text
src/ui_pages/iot_smart_fan.cpp
```

改动范围：

- 在 `iot_main_page.cpp` 启用已有风扇按钮和事件处理器。
- 在 `gui_super_knob.h` 中补充风扇菜单、风速页和转向页所需对象/状态。
- 风扇子菜单固定为“开关 / 风速 / 左右转动 / 返回”。
- 子菜单使用统一深色主题与字体回退；焦点用高亮底色、粗描边和外轮廓共同表示。
- 风速页使用 `1..100` 圆形刻度盘、进度弧和指针；左右页使用对称方向弧显示相对转量。
- 复用现有 `fan_img.c` 和 `fan_big_img.c`，不重新引入图片资源。
- 页面切换遵循现有 `SUPER_PAGE_BUSY` 保护方式，避免切屏期间重复输入。
- 页面销毁或离开时停止未发送的方向动作，避免离开页面后风扇继续转动。

## 4. 分阶段实施与验收

### 阶段 A：冻结基线（已完成）

- 构建当前工程并记录结果。
- 确认 `.pio`、临时文件、真实凭据和 token 工具均不进入 Git。
- 将已有显示修复、项目配置和文档形成一个基线提交。

验收：`git status --short` 为空，当前固件可编译。

### 阶段 B：电脑端动作标定（待实机观察）

- 单独发送一次 `turn-left`，观察是否成功和实际转动量。
- 单独发送一次 `turn-right`，验证对称性。
- 连续发送少量动作，测量安全的最短命令间隔。
- 记录单动作约对应的角度；如果步长不稳定，则定义为“相对转量”而非显示虚假绝对角度。

验收：确定方向动作是否可用、单步效果和最大发送频率。此阶段会导致风扇实际转动，执行前再次确认。

### 阶段 C：最小 MIoT 传输实现（实机读取通过，待异常恢复测试）

- 先实现握手和只读 `get_properties`。
- 使用电脑端读取到的状态作为对照。
- 加入错误日志，但日志禁止打印 token、Wi-Fi 密码或完整密钥。

验收：ESP32 串口能稳定读取与米家 App 一致的风扇状态；断网后任务可恢复且不阻塞界面。

当前实测：2026-09-07 已由 ESP32 成功读取风扇状态；断网与恢复场景留待阶段 G。

### 阶段 D：风速写入（已完成）

- 实现 `setSpeed()` 和范围检查。
- 先用固定测试值验证，再接旋钮。
- 加入合并发送和最终值保证，快速旋转后风扇最终值必须与屏幕一致。

验收：慢转、快转、反向快速调节均能在短时间内收敛到显示值；数值始终处于 1–100。

### 阶段 E：风扇菜单与返回逻辑（已完成）

- 启用主页面风扇入口。
- 实现“风速 / 左右转动 / 返回”三个子项。
- 所有确认和返回均只使用轻触。
- 暂时用模拟控制器验证页面，不依赖风扇在线。

验收：所有页面可反复进入退出，无死页、重复对象、焦点丢失或触摸长按依赖。

### 阶段 E2：电源与视觉优化（已烧录，待实机验收）

- 增加与风速、左右转动并列的“开关”项，轻触一次切换一次。
- 开关命令由异步控制任务发送；界面先响应，随后由设备状态回读校正。
- 开启状态显示绿色 `ON`，关闭状态显示红色 `OFF`。
- 统一菜单字体、尺寸、色彩和间距，并加粗选中框及外轮廓。
- 风速页改为钟表式刻度盘，旋钮同步控制数值、进度弧和指针。
- 左右页改为方向圆弧和相对转量显示；标定完成前仍不发送实际转向命令。

验收：连续切换开关时最终状态正确；菜单选中项清晰；两个调节页无文字缺失、重叠或越界。

### 阶段 F：左右转动映射（已启用，待实机标定）

- 根据阶段 B 的实测步长建立“编码器增量 → 待执行动作数”的映射。
- 旋钮转得越多，动作累计越多；方向改变时抵消尚未执行的反向动作。
- 设置每次进入页面的相对零点，不宣称设备具有可读取的绝对朝向。
- 到达机械边界或设备拒绝动作时清空对应方向的积压。

验收：小幅、连续、快速反向操作均可控；退出页面后立即停止继续发送。

### 阶段 G：整机回归

验收：原有功能行为不变；网络异常不会卡住旋钮、显示或电机；Git 工作区干净。
